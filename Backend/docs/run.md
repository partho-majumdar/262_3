# Running the project

All commands are Windows PowerShell from the `Backend` directory. The
interpreter is the project venv, not a system Python:

```powershell
$py = 'E:\UIU\TRIMESTER - 11\Computer Security\CS_Project\Backend\.venv\Scripts\python.exe'
```

## 0. Environment

```powershell
& $py -m pip install -r requirements.txt
& $py -m playwright install chromium
```

The browser lands in `C:\Users\Asus\AppData\Local\ms-playwright`. Screenshot
capture is the only step that needs it.

## 1. Dataset

Source: `../Dataset/Phishing_URL_Dataset.csv` (PhiUSIIL), 235,795 rows,
SHA-256 `748ae7c7a677ac4ffc0eeefbee653dcef1d685b134ad2f5376596b92d79438ba`.

```powershell
& $py training/inspect_dataset.py --csv ..\Dataset\Phishing_URL_Dataset.csv
& $py training/make_splits.py --csv ..\Dataset\Phishing_URL_Dataset.csv --seed 42
```

Note both scripts take `--csv`, not `--config`; column names are auto-detected from
the file contents. Splits are 164,760 / 35,305 / 35,305 (train/val/test) and are
grouped by registered domain, so no domain appears in two splits.

`make_splits.py` overwrites `data/splits/` in place. Pass `--out` to build a second
split set without invalidating `data/manifest.csv` and anything trained from it.

## 2. URL-only model (P2)

```powershell
& $py training/train_url.py --config configs/dev.yaml
& $py training/leakage_experiment.py --config configs/dev.yaml
```

Evaluation is built into `train_url.py`; there is no separate `calibrate.py` or
`evaluate.py` step. Writes `checkpoints/url_model.pt`, `reports/metrics_url.json`, and
the leakage comparison. Test results are in `reports/metrics_url.json`; the headline
numbers and what they do and do not mean are in the final report.

## 3. Multimodal collection (P3)

Slow and network-bound. Expect tens of minutes per few hundred URLs.

```powershell
# smoke check first — always do this before a long run
& $py training/collect_multimodal.py --config configs/dev.yaml --n 6 --splits train --limit 6

# real run
& $py training/collect_multimodal.py --config configs/dev.yaml --seed 42 --n 700
```

A long run writes artifacts incrementally, so HTML file count under
`data/html/` climbing is the signal that it is alive. If it stalls with the count
frozen, the run is hung — stop it rather than waiting.

Reads and writes `data/manifest.csv`, `data/html/`, `data/screenshots/`, and
`reports/collection_report.md`. The collection report records the **availability
gap** (phishing-vs-legitimate success rate), which is the number that decides
whether fusion is worth doing at all. See `docs/limitations.md`.

A crawler row can claim `html_ok=True` while the artifact is absent, because the
readers return `None`/zeros instead of raising. Check the manifest against the
filesystem before reporting multimodal numbers.

## 4. Multimodal training (P4-P6)

```powershell
& $py training/train_multimodal.py --config configs/dev.yaml --modalities html vision fusion
```

Writes `checkpoints/{html,vision,fusion}_model.pt` and
`reports/metrics_{html,vision,fusion}.json`. Modality dropout is on during
training so the fusion model learns to work when inputs are missing — which is
the normal case at inference, not an edge case.

## 6. API

```powershell
& $py -m uvicorn app.api.main:app --host 127.0.0.1 --port 8000
```

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
Invoke-RestMethod http://127.0.0.1:8000/metrics
Invoke-RestMethod -Method Post http://127.0.0.1:8000/analyze `
  -ContentType 'application/json' -Body '{"url":"http://www.easydns.com"}'
```

There is **no authentication** (by requirement) and `/analyze` will fetch any
URL that passes the SSRF guard. Bind to `127.0.0.1` and put a reverse proxy in
front of it before anything else. `GET /health` reports the renderer posture
(`screenshot_service`) — check it rather than assuming.

## 7. Frontend

```powershell
cd ..\Frontend
npm install
npm run test
npm run typecheck
npm run build
npm run dev
```

The dev server proxies `/api` to `127.0.0.1:8000`, so run the backend first.
The `ModalityToggle` in the UI mirrors the backend's availability masks: toggle a
modality off and the response explains that the model did not see it, rather than
silently scoring as if it had.

## 8. Notebooks (optional)

The same pipeline, walkable cell by cell:

```powershell
& $py -m pip install -r requirements-notebooks.txt
& $py -m jupyter lab --notebook-dir notebooks
```

Notebooks import the production modules in `app/` and `training/` rather than
reimplementing them, so they cannot drift from the CLI. They are generated by
`notebooks/_build_notebooks.py`; edit the generator rather than the JSON. See
`notebooks/README.md`.

## Reproducibility

Seed 42 throughout (splits, model init, collection sampling). Each training run
writes its own `reports/metrics_*.json` including the resolved config, the seed,
row counts, and — for the vision model — whether pretrained weights actually
loaded, so a random-init backbone can never be reported as a pretrained one.

Known environment limits, stated up front:

- **CPU-only.** Practical PyTorch use is CPU; measured URL training throughput
  was ~0.37 s/step, which put the full profile at an estimated ~161 min/epoch.
  All reported runs use the `dev` profile (40,000 train rows, ResNet-18). The
  `full` profile is configured but was not run here.
- **Docker is absent**, so the containerised screenshot service could not be
  built or verified. Capture runs in-process with reduced isolation. See
  `docs/security.md` §4.
